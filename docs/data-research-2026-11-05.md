# 斗地主明牌残局的人类难度数据调研

检索日期：2026-11-05（Asia/Shanghai）。阶段：只读资料调研；未训练模型、未生成实验数据、未验证第三方求解器正确性。

## 结论

本次检索未发现可以直接用于目标训练的公开数据集：三人明牌残局 + 精确必胜策略 + 真人解题难度标签。这里是“未找到”，并非证明此类数据不存在。
找到了可下载的斗地主决策数据、少量现成明牌题、可生成候选题的求解器、商业题库的规则难度，以及以真人行为估计难度的方法。不能把这些合并宣称为现成人类难度数据。

目标是估计人解决残局时的推理负担与关键选择隐蔽程度。必胜性、机器搜索成本、人类难度、题目质量是不同变量。残局对最优对手的胜负可以确定，而真人通过率取决于人群、时间限制、提示、重试和对手在必败分支的应对方式。

## 最相关资源

### 1. ShuyaoGao/doudizhu-endgame-solver：优先调查的候选基础

- 来源：https://github.com/ShuyaoGao/doudizhu-endgame-solver
- 检查了 README、仓库文件树、endgame/puzzles.py、endgame/scan.py 和 endgame/solver.py。
- 支持二人和三人明牌，三人有地主和两名同队农民。求解接口可给各合法着法的胜负与一条示范线。
- puzzles.py 有 9 题：5 道二人、4 道三人；含答案与人工讲解。注释称答案经独立暴力求解器复核。本调研未执行复核。
- README 报告三人自对弈截取 3000 局面、三人均匀随机 1000 局面；另外两组二人扫描各 3000 和 1000。它们是扫描规模，不等于发布了 8000 条完整训练样本。
- scan.py 会统计胜着比例、唯一胜着、贪心策略失误和操作类别；内部最多积累 30 个示例，summarize 最终只输出前 10 个示例。现存 results/scan_decisive.json 主要是统计与精选示例。
- 达到节点预算的局面会跳过，可能系统性少收复杂局面；未来生成时需要完整保留 attempted/skipped/unknown。
- 唯一胜着、贪心失误均为机器代理标签，没有真人难度评分。
- 仓库声明代码 MIT，文档与教学素材 CC BY 4.0；实际复用需保留对应归属。
- 建议：先审计规则、农民合作、预算未知状态和状态规范化，再作为小规模数据生成候选。不能因为 README 写“精确”就跳过独立校验。

### 2. OpenDILabCommunity/MasterMind：真实存在的公开决策数据，但标签不匹配

- 来源：https://huggingface.co/datasets/OpenDILabCommunity/MasterMind
- 数据卡描述斗地主 500 个完整对局，490 训练、10 测试。
- question 表示局面，sentence 表示决策与策略分析；由 DouZero/RLCard 代理与模板生成。数据卡明确没有人工标注。
- HF 文件元数据核查：doudizhu/train_dataset.parquet 为 98,611,761 字节；test_dataset.parquet 为 899,370 字节。本次没有下载。
- 数据卡声明 Apache-2.0。卡片版本与论文扩展数据可能有差异；500 是卡片所述对局数，不能当作样本行数或套用到所有论文版本。
- 没有真人解题时间、通过率或难度分。不能直接作为目标监督数据。
- 可研究其状态表达和策略学习；是否可还原目标所需完整明牌状态，需以后抽样检查实际文件。

### 3. naturalleo/doudizhu_endgame 与其他旧求解器

- https://github.com/naturalleo/doudizhu_endgame
- https://github.com/WZ403809264/doudizhu_solver
- naturalleo 采用 C++、Negamax 与置换表，README 的状态结构为地主/农民两手牌，GPL-3.0。
- WZ403809264 明确输入先手、后手两家，并公开少量比较样例；未确认独立许可证。
- 都不是人类难度训练集，二人算法也不能不加修改地套到三人团队博弈。
- 旧 README 的“测试 50 关”不代表仓库里有 50 条可下载题库。本次文件树未见独立 50 题数据文件。

### 4. Hi8 在线残局：公开规则分级，非公开标注数据集

- https://hi8.com/g/doudizhucanju
- 两人明牌，入门/进阶/困难/大师四档。
- 分级依据包括手牌张数、开局必胜着法数量、后续关键关口、三种顺手策略是否失败。
- 网站说明记录第几次通过与是否看过答案，但未找到公开批量导出、可复用许可或真人行为数据下载。
- 可借鉴分级思路；其四档标签属于设计规则，不应当作经过真人校准的三人难度分。
- 未登录、未购买、未抓取受限题库。

### 5. RefGPT-Reason：有零星斗地主题，不能当可靠答案集

- https://huggingface.co/datasets/Mutonix/RefGPT-Reason
- 检索命中三人残局文本，但展示答案出现把地主与一名农民当作合作方等明显规则错误。
- 未审计全库、未统计斗地主题总量。只能作为低可信候选题线索；答案须丢开并重新精确求解，不能直接训练。
- 没有目标难度标签。

## 方法参考与行业线索

### 腾讯专利：以用户行为或模仿用户的代理评估难度

- https://patents.google.com/patent/CN110263937B/zh
- 文本讨论以人类对局训练的模型进行模拟对局，再按结果估计残局难度。
- https://patents.google.com/patent/CN107970608B/zh
- 文本涉及用历史用户通关行为给关卡和玩家评分。
- 这些是方法材料，不是数据下载页；未发现相应公开真人训练数据。专利描述也不是方法有效性的实证证明。

快手自动生成残局的行业介绍是另一条线索：
https://developer.cloud.tencent.cn/news/758453
它描述用强化学习与 minimax 筛选残局、参考用户体验；未找到对应公开数据。该二手文章邻近段落提到 ICLR 2020，不能据此将残局生成工作直接认定为该会议论文。

### Lichess：贴近目标的数据组织与真人难度校准范例

- https://database.lichess.org/#puzzles
- 公开国际象棋题，字段包括 FEN、Moves、Rating、RatingDeviation、NbPlays、Themes、Popularity。
- 官网解释每次人类做题被看成玩家与题目的 Glicko2 对局。
- Rating（难度）与 Popularity（评价）分开，适合借鉴“难”和“好”分开建模。
- 棋种不同，不能把其数值直接当作斗地主标签。未下载其大文件。

### 数独人类难度研究

https://arxiv.org/abs/1403.7373
研究以 1700 多道数独和数百名解题者评估难度模型，区分单步逻辑复杂度和步骤依赖结构。
可参考这种问题分解，但不代表对斗地主已经验证。

## 下一阶段建议（未批准、未实施）

1. 明确目标人群：会规则的普通玩家、经常打牌的人、残局高手；定义限时、提示和重试条件。
2. 先用可靠求解器筛出合法三人必胜局面，输出完整分支证据；预算超限保留 unknown，不能标成输。
3. 使用多个独立特征描述候选难度：关键选择数量、合理但错误的候选、错误何时才能被反驳、农民配合、拆牌或让牌是否必要。
4. 第一阶段只把这些叫“结构难度/代理分”，不要宣称预测真人难度。
5. 收集小规模真人首轮通过率、无提示解题时长、错误动作、提示、重试、水平，以及独立的题目质量评价；控制重复曝光。
6. 用真人数据校准排序或等级模型，报告难度与质量两个输出。同构局面、同题变体和同源轨迹必须分组划分训练/测试，避免模板泄漏。
7. 在真人标签不足前，先训练大模型打代理分很可能只是昂贵地复刻人工公式。小模型/排序基线更容易验证是否确实学到了真人难度。

## 存储策略

- 本地不克隆、不下载数据、模型或论文。
- 服务器仅留这个轻量仓库工作副本；代码、报告、小型清单进 Git。
- 第三方大型公开数据优先保存固定版本、URL、大小与校验值，按需流式读取。
- 后续自有大型数据与权重再选 Releases、LFS 或数据仓库，不将反复更新的二进制直接堆进 Git 历史。
- GitHub 普通 Git 单文件超过 100 MiB 会被拦截；“都上传 GitHub”不能保证后续克隆不占空间。
- https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github
- 不自动删除实验原始证据；需要回收时先保证远端可读且校验一致。
